# VOFA 下管驱动波形

## 使用

1. 在 Keil 编译并下载工程，VOFA 选择 **JustFloat** 协议。
2. 默认 `vofa_mode = 1`、`vofa_pwm_auto_repeat = 1`，反复抓取并回放。通道如下：

   | 通道 | 引脚 | 信号 |
   |---|---|---|
   | CH0 | PB13 | LIN1 |
   | CH1 | PB14 | LIN2 |
   | CH2 | PB15 | LIN3 |
   | CH3 | — | 回放时的实时 A 相电流（A） |
   | CH4 | — | 回放时的实时 B 相电流（A） |
   | CH5 | — | 回放时的实时 C 相电流（A） |
   | CH6 | — | 记录编号，同一段内保持不变 |
   | CH7 | — | 段内采样点编号，0～3999 |

   CH0～2 每路数值为 0 或 1，按物理桥臂编号显示，不随 `calibration.phase_reversed` 交换。CH3～5 保留用户添加的电流值，但它们是在回放时读取，未与 PWM 一起录入，不能与脉冲逐点对应，也不能用 0.25 us 点间隔分析电流频率。

   观察脉冲时先只显示 CH0，纵轴设为 -0.2～1.2；随后按需显示 CH1/CH2。隐藏 CH3～7，避免电流或编号把自动纵轴范围拉大，使脉冲看起来像直线。导出 CSV 时保留全部通道，以便根据编号分段。

3. VOFA 的点间隔设为 **0.00025 ms（0.25 us）**。一次记录 4000 点，覆盖 1 ms，约 20 个 PWM 周期；波形窗口至少保留 4000 点。放大到约 200 点，可以观察一个约 50 us 的 PWM 周期。
4. 打开 VOFA 串口后，第一次自动抓取等待 PWM 输出开启。当前工程默认关闭 PWM，需要按原来的按键开启。之后按“采集 1 ms → 完整发送 → 再采集”循环，记录多久由你在 VOFA 端决定。首次采集开始后，即使 PWM 被关闭也继续抓取，方便观察关断状态。
5. 想固定一段慢慢看：在 Keil Watch 中将 `vofa_pwm_auto_repeat` 改为 `0`，当前记录发送完就停住。随后将 `vofa_pwm_capture_request` 设为 `1` 可再抓一次，也允许抓取 PWM 关闭时的引脚状态；手动请求在已有采集/回放结束后执行。将 `vofa_pwm_auto_repeat` 改回 `1` 恢复循环。
6. `vofa_pwm_sent_samples == 4000` 表示本次记录已通过 USB 完成发送；循环模式下紧接着开始新记录，点数清零。再次关闭/打开 VOFA 串口会重新等待首次抓取。
7. 恢复原来的电流等实时通道：把 `vofa_mode` 改为 `0`，清空图表并恢复之前的显示点间隔（原配置为 0.05 ms）。要让重新上电也默认显示原通道，将 `vofa.h` 中的 `VOFA_DEFAULT_MODE` 改为 `VOFA_MODE_TELEMETRY`。

注意：USB 是采集完后的回放通道，发送速度不是采样速度。发送期间存在采集空档，这不是无间断的高速记录。CH6 变化、CH7 从 3999 回到 0 表示新的一段；横轴的点间隔只适用于段内，拼接后的总时间不代表实际经过时间。分析脉宽、周期时选同一段内的数据，不要跨段测量或对全部拼接数据做 FFT。

## Keil 观察变量

| 变量 | 含义 |
|---|---|
| `vofa_mode` | 0：原来的实时数据；1：下管驱动记录回放 |
| `vofa_pwm_auto_repeat` | 默认 1：反复抓取并回放；0：当前记录结束后停止自动重抓（首次自动抓取和手动请求仍有效） |
| `vofa_pwm_capture_request` | 写 1 排队抓取一次，受理后自动清 0 |
| `vofa_pwm_sent_samples` | 当前记录已经完成 USB 发送的点数，0～4000 |
| `pwm_capture.state` | 0：空闲/等待；1：采集中；2：记录完成，可回放；3：采集错误 |
| `pwm_capture.error` | 0：正常；1：外设占用；2：时钟不匹配；3：DMA 初始化失败；4：DMA 启动失败；5：DMA 传输错误；6：采集超时 |
| `pwm_capture.sample_period_us` | 名义采样间隔，当前 0.25 us |
| `pwm_capture.completed_count` | 成功采集次数 |

若没有波形，先确认 PWM 已开启，再看 `pwm_capture.state/error` 和 `vofa_pwm_sent_samples`。等待首次自动抓取时 state 为 0；循环时 state 在 1、2 之间切换，`completed_count` 持续增加；单次模式发送完成后 state 保持 2。发生采集错误时停在 3，不会自动反复重试；检查错误原因后可手动请求重抓。三路全零也可能是实际输出关闭状态，不能单凭全零断言 DMA 出错。

## 实现与资源

- `User/bsp/pwm_capture.c/.h`：TIM6 更新请求触发 DMA2_Channel1，读取 `GPIOB->IDR` 到 4000 个 `uint16_t` 的 SRAM 数组，占用 8000 字节。
- 当前 TIM6 时钟 160 MHz，PSC=0、ARR=39，名义请求频率为 4 MHz。代码根据实际 APB1 时钟计算分频，并要求整除。
- DMA 普通模式，采满自动停止搬运。主循环轮询完成/错误标志，停止 TIM6；没有逐点中断或等待采满的阻塞循环。发生 DMA 错误或超过 10 ms 尚未完成时丢弃本次记录，保留错误码。
- `User/app/vofa.c`：每批打包最多 16 个完整的八通道 JustFloat 帧，当前每批最多 576 字节；USB 缓冲区按最多 18 通道预留 1216 字节，并检查通道数和剩余容量。USB 完成上一批后才推进回放位置和复用发送缓冲区；整段最后一批完成后才允许下一次 DMA 覆盖采样数组。重新打开串口丢弃旧会话的剩余记录。
- TIM6 和 DMA2_Channel1 由这个 User 模块独占、按需初始化，不由 CubeMX 生成。以后在 CubeMX 中分配资源时要保留这两个外设。当前 `.ioc` 和 Core 生成代码无需更改；Keil `User/bsp` 分组已经加入新模块。
- 记录使用 DMA2 低优先级，但仍有总线开销；它不是完全无扰动的测量。FOC、ADC 和 TIM1 的原有配置保持现状。

## 波形含义和精度

- 采集的是 PB13/PB14/PB15 的实际数字电平，不是根据 CCR 合成的波形。
- 1 表示驱动芯片 LIN 输入为高，0 表示低。当前 PWM1 互补输出在 `CNT > CCR` 区间给出下管导通指令（比较边沿附近除外）。
- 这里没有采到驱动芯片内部硬件死区之后的 MOS 栅极电压，也没有测到电流放大器的模拟建立时间。
- 0.25 us 是名义采样间隔；GPIO 输入路径和 DMA 总线仲裁会产生延迟/边沿不确定性。窄于采样间隔的脉冲可能漏掉，不能据此判断纳秒级死区。
- TIM6 采集起点不与 TIM1/ADC 触发对齐。这三路可以直接比较彼此的电平时序；本功能没有提供 ADC 精确采样时刻标记。
